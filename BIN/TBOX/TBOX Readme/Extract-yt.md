# 📺 Модуль: YouTube Content Extractor (v3.20+)
**Статус:** Стабильный  
**Вход:** URL или Video ID  
**Выход:** `.txt` файл в `02_TXT/` (планируется `.docx` в `03_DOC/Originals/`)

---

## 🛠 Функционал и параметры
Скрипт предназначен для «добычи» текстового сырья из видеолекций. Он берет на себя всю грязную работу по обходу блокировок YouTube и структурированию метаданных.

### ⚙️ Интеграция с конфигом (config.txt)
* **API & Paths:** Скрипт динамически вычисляет корень проекта (`BASE_DIR`).
* **Логирование:** Использует параметр `LOG_FILE` (по умолчанию `factory.log`). Все события пишутся в общий журнал завода с меткой `[extract_yt v3.20]`.
* **Цель:** Жестко направляет результат в `02_TXT/`.

### 🌍 Языковая политика
Скрипт ищет субтитры по приоритету:
1.  **Иврит (`he`, `iw`)** — основной рабочий язык.
2.  **Английский (`en`)** — резервный.

---

## 🏗 Логика именования и хранения
Каждый файл получает уникальный системный ID, чтобы избежать дубликатов:
`ГГММДД_ЧЧММ-Автор-ДатаЗагрузки-ID.txt`

**Внутри файла сохраняется «шапка»:**
* Название видео (TITLE)
* Прямая ссылка (LINK)
* Имя автора/канала (AUTHOR)
* Текстовое тело лекции (очищенное от таймкодов и лишних переносов).

---

## 📅 План развития (Roadmap)
В будущих версиях запланировано внедрение следующего функционала:

1.  **Параллельный экспорт в DOCX:** * Создание структурированного документа на языке оригинала.
    * Автоматическое сохранение по пути: `03_DOC/Originals/`.
2.  **Синхронизация с транслятором:** * Автоматическая передача созданного оригинала в очередь на перевод сразу после загрузки.
3.  **Расширенная обработка аудио:**
    * Если субтитры отсутствуют, скрипт должен предлагать передать видео в модуль `transcribe.py` для распознавания речи (STT).
